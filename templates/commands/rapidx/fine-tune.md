name: rapidx:fine-tune
description: "Apply learned codebase knowledge to update skills, agents, rules, and platform configs"
allowed-tools:
  - Read
  - Write
  - Bash
  - Glob
---

<objective>
Take the knowledge artifacts in `.rapidx/knowledge/` and systematically update the installed RapidX skills, agents, rules, and all platform configurations so every AI tool reflects the project's actual patterns, conventions, and architecture decisions.

Think of this as "applying the training data" — `/rapidx:learn` collects knowledge, `/rapidx:fine-tune` applies it.

Usage:
  /rapidx:fine-tune              → Apply all available knowledge
  /rapidx:fine-tune --skills     → Update skills only
  /rapidx:fine-tune --agents     → Update agents only
  /rapidx:fine-tune --rules      → Update rules only
  /rapidx:fine-tune --platforms  → Regenerate all platform configs
  /rapidx:fine-tune --preview    → Show what would change without writing
</objective>

<process>
## Step 1 — Load knowledge artifacts

Read all files in `.rapidx/knowledge/`:
- `code-patterns.md`
- `architecture.md`
- `guidelines.md`
- `domain.md`
- `mandates.md` (org policy / governance — treat as hard constraints)
- `security.md` (security artifacts and required controls)
- `reference.md` (exemplary modules to mirror)
- `graph.json` + `GRAPH_REPORT.md` (structure, hubs, coupling)
- `adr-index.md` (if exists)
- Any user-added `.md` files

Also read:
- `.rapidx/stack.json`
- Active profile from `.planning/config.json`

## Step 2 — Update installed skills

### coding-standards skill
Append to `.claude/rules/` or installed `coding-standards` skill:
```
## Project-Specific Standards (Learned {DATE})

### Naming Conventions
{from code-patterns.md → Naming Conventions section}

### Module Structure
{from code-patterns.md → Module Structure section}

### Anti-patterns (Do NOT use in this project)
{from code-patterns.md → Anti-patterns section}
```

### backend-patterns skill (if installed)
Add project-specific API and service patterns.

### frontend-patterns skill (if installed)
Add project-specific component and state patterns.

### architecture-copilot skill
Inject full architecture knowledge map.

## Step 3 — Update installed agents

### planner agent
Prepend to planning context:
```
## Project Architecture Context (from /rapidx:learn-arch)
{summary from architecture.md}

## Active ADRs that constrain planning:
{list of accepted ADRs from adr-index.md}
```

### architect agent
Inject full architecture knowledge.

### code-reviewer agent
Add project-specific patterns to review checklist:
```
## Project-Specific Review Checks
- Does this follow [naming convention]?
- Does this use [approved pattern] for [concern]?
- Does this violate ADR-{N}?
```

### security-reviewer agent
Add domain-specific security patterns from guidelines.

## Step 4 — Update platform configurations

### Claude Code (CLAUDE.md)
Add section:
```markdown
## Project Knowledge (Auto-generated by /rapidx:fine-tune)

### Code Patterns
{key patterns from code-patterns.md}

### Architecture
{summary from architecture.md}

### Anti-patterns to Avoid
{from code-patterns.md anti-patterns}
```

### VS Code Copilot (.github/copilot-instructions.md)
Append learned patterns to the Copilot instructions file.

### Cursor (.cursor/rules/)
Create/update `.cursor/rules/project-patterns.mdc`:
```yaml
---
description: Project-specific code patterns (learned from codebase)
globs: ["**/*.ts", "**/*.tsx"]  # adjust per stack
---

{code patterns}
```

### OpenCode (.opencode/instructions/)
Update with project patterns.

### Codex (.agents/skills/)
Update skill files with project context.

### invariant-catalog agent + catalog
Use `mandates.md`, `security.md`, and the architecture/graph knowledge to PROPOSE
invariants. If the user agrees, hand off to `/rapidx:invariant-catalog --from-knowledge`
so the rules become enforced checks that run on every execute phase.

### Inject graph awareness into architect/planner/code-reviewer
From `GRAPH_REPORT.md`, add a short "hub modules / core contracts" note so agents
know the blast radius of changes and avoid breaking high-coupling interfaces.

## Step 5 — Sync specs index

If `specs/` exists, generate/update `specs/INDEX.md`:
```markdown
# Spec Index

| # | Feature | Status | Created | Stories |
|---|---------|--------|---------|---------|
| 001 | {name} | {Draft/Reviewed/Planned/Implemented} | {date} | {N} |
```

## Step 6 — Output

```
Fine-tuning Applied

  Knowledge sources: {N} files
  
  Skills updated:
    coding-standards    ✓ (+{N} project patterns)
    backend-patterns    ✓ (+{N} API patterns)
    architecture-copilot ✓ (full arch map injected)

  Agents updated:
    planner             ✓ (+architecture context)
    architect           ✓ (+ADR decisions)
    code-reviewer       ✓ (+{N} project-specific checks)
    security-reviewer   ✓ (+domain security patterns)

  Platform configs updated:
    CLAUDE.md           ✓
    copilot-instructions.md ✓
    .cursor/rules/      ✓
    .opencode/instructions/ ✓

  Run /rapidx:knowledge-sync to push changes to all platforms.
```
</process>
